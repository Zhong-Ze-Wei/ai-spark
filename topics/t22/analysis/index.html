为什么这样整理

这不是一个已经有答案的问题

8 月 25 日，数读问：普通公司为什么还需要专门的 Agent？niy🔆回应，当前仍有垂类需求，但担心大平台、模型公司直接进入应用层，也认为合适的商业模式尚未找到。这里保留的是担忧和问题，不是市场已淘汰谁的统计。[81][82]

有需求，和能持续做生意，是两关

一关是功能会不会被平台自带；另一关是即使有人需要，客户是否会长期使用、愿意付钱。接通 API、跑出演示，只完成了其中一部分。原文既没有证明垂类都会消失，也没有给出一条保证成功的路线。

剩下的价值，需要逐项去验

行业数据、接入原有流程、长期稳定、交付服务和使用方便，都值得看。但不能列出来就叫“护城河”：仍要证明客户真的用了，结果值得付出的成本。[1][2]

niy🔆的发言是行业判断与担忧，不是已发生的市场淘汰统计。没有收入、留存或客户数据，不能评估具体商业前景。

原文提出的问题

这里有两种不同风险

一种是技术功能被平台直接提供；另一种是即使功能有人需要，也无法证明客户会持续使用和付费。把 API 接起来、把演示做出来，只覆盖了一部分价值链。原文没有证明所有垂类都会消失，也没有给出成功路线。

可继续验证的差异化条件

行业数据接入、流程嵌入、长期可靠性、交付服务和使用便利，都可能是进一步考察的方向。这里只列作验证问题，而不是声称哪一项已经构成护城河。应回到用户是否真正使用、成果是否值得成本。[1][2]
